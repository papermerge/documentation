# 3.5.3 - not yet released

## Async Instead of Sync

This enhancement is related to performance.
Simply put, the REST API core server can now handle many more concurrent connections.
This is possible because its internal mechanics have changed:
instead of handling connections and database requests synchronously, they are now handled asynchronously.

## Home/Inbox DB Checks

This enhacement brings following database schema changes:
`users.home_folder_id` and `users.inbox_folder_id` have now "NOT NULL" database constraint.
This means that it is guaranteed on the database level that user entity will always have
an existing home/inbox folder. To make this change work technically it was necessary to
change `nodes` table `nodes_user_id_fkey` foreign key contrainst to "deferrable".

The point of this change is to make sure that unpleasant situation when user is created
but he/she has no home/inbox folder associated won't occur.

## Length Limit on Users Columns

This change alters database schema. This is change is related to security.
Following columns of ther `users` table feature now an upper limit:

- email: limited to 254 characters
- password: limited to 255 characters
- username: limited to 150 characters
- first_name: limited to 100 characters
- last_name: limited to 100 characters
